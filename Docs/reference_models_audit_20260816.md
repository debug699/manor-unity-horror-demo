## 结论摘要

- 参考目录共发现 **67 个 FBX**，全部可以被 Blender 导入。
- 没有发现 `.fbm` 文件。`.fbm` 通常是 Tripo/贴图缓存或工程附属目录，不是 Unity 必需格式；当前 FBX 旁边已有贴图文件即可继续工作。
- 当前房间文件夹有 G01-G08、G10-G12，**缺少 G09 文件夹**。G09 儿童房双区仍需要补一个独立房间资产或由现有儿童房模块组合。

- `主楼主用/ai查看修改.fbx` 有 **4292 个 Mesh 对象**，`加工木屋主用/已拆开，可能需要重做.fbx` 有 **3112 个 Mesh 对象**。它们保留了过度碎片化结构，不能直接作为最终 Unity Prefab；已生成非破坏性的合并外壳暂存文件，但门窗和碰撞仍需单独制作。
- `人物tom/不用拆.fbx` 有 41 根骨骼，但没有动画剪辑；可以继续绑定/补动画。
- `屠夫/不用拆.fbx` 和 `怨鬼小孩/不用拆.fbx` 都是静态网格，没有骨骼；要做追逐、抓取、石化或残影动画，需要后续绑定骨骼。

## 门窗与自由度审计

### 原则

整体房屋 Mesh 无法可靠支持开门、开窗和翻越。不要尝试在 Unity 中直接旋转整栋房子，也不要给整个房屋加一个大 BoxCollider。

### 推荐处理

1. 建筑外壳：保留墙、地板、屋顶和不可动窗框。
2. 可交互门：单独制作 `Door_Frame`、`Door_Leaf`、`Door_Handle`、`Door_Latch`，门扇原点放铰链侧。
3. 可翻越窗：墙体保留真实空洞，窗框固定，窗扇/木板单独制作 `Window_Leaf`、`Window_Board`。
4. Unity 碰撞：建筑用可见墙体分段碰撞；门扇、柜门、窗扇使用独立碰撞体；不要覆盖整屋。
5. Blender 修复：如果门窗已融合，优先制作“独立交互门套”覆盖原入口，不必破坏原始高模。

## 地下通道审计

当前 Unity 场景已经存在地下灰盒对象，包括地下楼梯、B01 连接通道、过渡房和 B02 祭祀室。当前最有效的流程是：

1. 保留现有灰盒作为尺寸和路线基准。
2. 用厨房活板门 FBX 替换入口视觉，并保留独立 Pivot/Collider。
3. 用墙体、地板、楼梯围栏和小块木板模块逐段替换 B01。
4. 用法阵、立柱、锁魂钉、祭坛和遗骸布置 B02。
5. 先验证玩家能从 G03 进入 B01，再从 B01 到达 B02；最后再做潮湿石墙、雾和灯光。
